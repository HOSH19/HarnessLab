## LangSmith experiment table fix

### Problem

In the experiment table, the **Outputs** column sometimes showed `final_reply` prose (e.g. *"The incident appears to be caused by…"*) instead of the classification label (`infrastructure`), even when classification was correct in the run detail view.

### Cause

LangSmith’s default preview heuristic picks the **longest top-level string** in run outputs. `final_reply` often won over `classification`.

### Fix (two parts)

1. **Top-level `output` field** — set to the classification value (LangSmith table preview convention).
2. **Nest long fields under `details`** — run outputs shape:

```json
{
  "output": "infrastructure",
  "classification": "infrastructure",
  "error_count": 0,
  "details": {
    "final_reply": "...",
    "graph_trajectory": { ... }
  }
}
```

Evaluators use `run_output_field()` which reads from `details` when needed.

**Re-run experiments** after pulling this branch so datasets and runs pick up the new output shape.

## Commands reference

### Run all tasks (LangSmith upload)

```bash
python -m harnesslab run examples/research_agent --harness minimal --tasks 4 --dataset research-agent-stress
python -m harnesslab run examples/incident_manager --harness minimal --tasks 6 --dataset incident-manager-stress
```

### Local compare (no LangSmith)

```bash
python -m harnesslab compare examples/research_agent --local -o report.html
python -m harnesslab compare examples/incident_manager --local -o incident-report.html
```

If `python` is not found:

```bash
./scripts/install.sh
# or
python3 -m harnesslab ...
```
